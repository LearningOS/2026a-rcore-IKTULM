# 实验一：多道程序、时钟与 trace

## 实验目标

本实验在第三章静态多道程序系统基础上完成 `get_time` 和 `trace` 两个功能。重点是理解用户态与内核态之间的寄存器保存、陷阱返回和任务私有状态。

## 实现过程

`sys_get_time` 从 SBI/RISC-V 时钟读取微秒数，将其拆分为秒和微秒后写入用户提供的 `TimeVal`。为了让不同任务拥有独立的系统调用统计，我在任务控制块中保存了按 syscall ID 索引的计数数组，并在陷阱分发到具体系统调用前更新计数，使查询本身也计入 trace 查询结果。

`sys_trace` 支持三种请求：

1. 读取用户地址上的一个字节；
2. 向用户地址写入一个字节；
3. 查询指定 syscall ID 的累计次数。

读写前会检查地址是否属于当前应用的代码、数据或用户栈，非法地址返回 `-1`。该设计避免了应用借助 trace 访问内核地址。

## 测试结果

使用官方 `rCore-Tutorial-Checker` 第三章测试，`ch3_sleep`、`ch3_sleep1`、`ch3_trace` 以及多任务 yield 测试全部通过，结果为 `7/7`。

## 总结

本实验强化了对陷阱上下文、任务切换和系统调用副作用的理解。实现中特别注意到计数更新必须在 syscall 分发前完成，否则查询自身不会被计入，与课程测试语义不一致。
